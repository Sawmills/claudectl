# SAW-12448: Give an Interactive `exec` Child the Terminal Foreground

`claudectl exec` starts its child in a new background process group, so a child that reads the terminal stops (state `T`) and Ctrl-C never reaches it. The fix makes the child's group the terminal's foreground group when claudectl itself owns the foreground, and gives the foreground back when the child exits. The `launcher` script runs `claudectl exec`, so the same fix covers it.

## Cause

`run_in_dir` calls `set_process_group`, which sets `process_group(0)` (`src/exec.rs:858`, `src/exec.rs:1231`). The child becomes leader of a new group, but nothing calls `tcsetpgrp`, so the terminal foreground stays with claudectl's group. The terminal driver sends SIGTTIN or SIGTTOU to the child on its first terminal read or `tcsetattr`, and the child stops. Ctrl-C goes to the foreground group (claudectl), and claudectl forwards SIGINT to a stopped group. The comment at `src/exec.rs:855` and `README.md:184` record this as a known limit of the original design.

Reproduction on claudectl 0.1.8 (Mac, a pty from `script -q /dev/null`, a shebang child that runs `read x`):

```
claudectl exec  PID 40258  PGID 40258  TPGID 40258  Ss+
readx.sh child  PID 40716  PGID 40716  TPGID 40258  T
```

The child does not leave state `T` until it receives SIGTERM and SIGCONT. A copy of `/bin/sh` cannot be the child for this test: `exec` runs a snapshot of the executable, and macOS kills a copied platform binary with SIGKILL.

## Fix

Keep the separate process group. The group is what lets `teardown_group` and the signal forwarder reach the child's descendants without touching claudectl.

1. Before the spawn, decide `interactive`: stdin is a terminal and `tcgetpgrp(0) == getpgrp()`. A claudectl that runs in the background, in a pipe, or under CI keeps today's behavior.
2. If `interactive`, the `pre_exec` closure calls `tcsetpgrp(0, getpid())` with SIGTTOU blocked. Rust std calls `setpgid` before the `pre_exec` callbacks (`std/src/sys/process/unix/unix.rs`), so the group already exists at that point. `spawn` returns only after `exec` succeeds, so the child owns the foreground before it runs.
3. A guard in the parent gives the foreground back with `tcsetpgrp(0, getpgrp())`, with SIGTTOU blocked. The guard runs right after the child exits (before `teardown_group`), and on a spawn failure after the child's `pre_exec`.
4. Signals then follow the shell job model. The terminal delivers Ctrl-C and SIGWINCH to the child's group directly. Claudectl is outside the foreground group, so it does not receive them and does not forward a second copy. SIGTERM and SIGHUP sent to claudectl still go through the existing forwarder.
5. Update the comment at `src/exec.rs:855` and the README section at line 184: `exec` now supports interactive children.

Out of scope: job control (Ctrl-Z) and restoring terminal modes after a crashed child. A child that stops on SIGTSTP leaves claudectl waiting, as it does today.

## Tests (Test First)

Add a pty test to `tests/exec_test.rs`, with no new dependency. The test opens a pty with `posix_openpt`, `grantpt`, `unlockpt`, and `ptsname`. It starts `helper_run_one_alias` with `setsid`, `TIOCSCTTY`, and the pty as stdin, stdout, and stderr. The fake child records its PGID and `tcgetpgrp`, then runs `read line`.

- `interactive_child_reads_the_terminal`: the test writes `hello\n` to the master. The child records `hello`, and the helper exits 0 within 10 s. Before the fix, the child stops and the test times out.
- `ctrl_c_reaches_an_interactive_child`: the child traps INT and records it. The test writes `\x03` to the master, then checks that the record exists and that the helper exits.
- `foreground_returns_to_claudectl_after_exit`: after the child exits, the helper records `tcgetpgrp(0) == getpgrp()`.

The existing non-terminal tests stay unchanged and prove that the old path is intact. The live proof stays with HQ: a pinned Claude lane in a herdr pane shows the TUI, and Ctrl-C reaches Claude.
