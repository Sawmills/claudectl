# SAW-12448: Give an Interactive `exec` Child the Terminal Foreground

`claudectl exec` starts its child in a new background process group, so a child that reads the terminal stops (state `T`) and Ctrl-C never reaches it. The fix makes the child's group the terminal's foreground group when claudectl itself owns the foreground, follows the shell job model for Ctrl-Z and `fg`, and gives the foreground back when the child exits. The `launcher` script runs `claudectl exec`, so the same fix covers it. HQ approved this plan with changes S1-S7 (rule 57 challenge on 6d511d3); this revision folds them in.

## Cause

`run_in_dir` calls `set_process_group`, which sets `process_group(0)` (`src/exec.rs:858`, `src/exec.rs:1231`). The child becomes leader of a new group, but nothing calls `tcsetpgrp`, so the terminal foreground stays with claudectl's group. The terminal driver sends SIGTTIN or SIGTTOU to the child on its first terminal read or `tcsetattr`, and the child stops. Ctrl-C goes to the foreground group (claudectl), and claudectl forwards SIGINT to a stopped group. The old comment at `src/exec.rs:855` and `README.md:184` recorded this as a known limit.

Reproduction on claudectl 0.1.8 (Mac, a pty from `script -q /dev/null`, a shebang child that runs `read x`):

```
claudectl exec  PID 40258  PGID 40258  TPGID 40258  Ss+
readx.sh child  PID 40716  PGID 40716  TPGID 40258  T
```

A copy of `/bin/sh` cannot be the child for this test: `exec` runs a snapshot of the executable, and macOS kills a copied platform binary with SIGKILL.

A second defect showed up during the work. macOS `waitid` reports a stopped child (`CLD_STOPPED`) even without `WSTOPPED`. In 0.1.8 a stop of a non-interactive child therefore counts as an exit, and claudectl then blocks in the reap of a stopped child.

## Fix

The child keeps its separate process group, because `teardown_group` and the signal forwarder use it to reach the child's descendants without touching claudectl.

1. `interactive` is true only when `tcgetpgrp(0)` succeeds and equals `getpgrp()` (S7). A claudectl in the background, in a pipe, or under CI keeps the old path.
2. If `interactive`, a `pre_exec` callback calls `tcsetpgrp(0, getpid())`. It saves the signal mask, blocks SIGTTOU for the call, and restores the saved mask, so Claude and its tools never inherit a blocked SIGTTOU (S2). Rust std calls `setpgid` before the `pre_exec` callbacks, and `spawn` returns only after the `exec`.
3. `foreground::reclaim` gives the foreground back to claudectl right after the child exits (before teardown), but only while the child's group still owns it: after Ctrl-Z and `bg` the shell owns it, and a background claudectl must not take it (Architect review). After a failed spawn it reclaims only from a group with no live process. It ignores EIO, ENOTTY and ENXIO after a hangup; the exit code, the `exited` receipt and the `~/.claudectl/run` cleanup do not change (S3).
4. Ctrl-Z (S1): an interactive run waits with `WSTOPPED`. When the child stops, claudectl takes the foreground back and stops itself with a thread-directed SIGTSTP (`pthread_kill`), as the terminal would; a process-directed `kill(0, SIGTSTP)` could go to another thread and leave this one running for a moment, which made the `bg` test fail about once in 13 runs on Linux. When claudectl is continued, it gives the foreground to the child again if claudectl was resumed in the foreground (`fg`), then sends SIGCONT to the child's group. A non-interactive stop never suspends claudectl; claudectl waits until the child is continued and exits.
5. SIGCONT follows every forwarded signal (SIGTERM, SIGINT, SIGHUP) and every teardown SIGTERM, because a stopped process acts on a handled signal only after it is continued (S5; SIGINT added after the Architect review).
6. Signals follow the shell job model. The terminal delivers Ctrl-C and SIGWINCH to the child's group directly. Claudectl is outside the foreground group, so it does not forward a second copy.
7. Pane close (S6): the kernel sends SIGHUP to the foreground group, which is the child's group. The shell that started claudectl also sends SIGHUP to its jobs, and claudectl forwards it with SIGCONT. Cleanup runs after the child exits; `reclaim` then fails with EIO, and claudectl ignores that.
8. The comment at `src/exec.rs:855` and the README `exec` section describe the interactive behavior (S7).

Out of scope: restoring terminal modes after a crashed child.

## Tests

Seven tests in `tests/exec_test.rs` use no new dependency. A `PtyJob` opens a pty with `posix_openpt`, starts a job-control shell (`set -m`) as the leader of a new session on it, and runs `helper_run_one_alias` as the shell's foreground job. The shell is `/bin/dash` when present, because macOS `/bin/sh` (bash 3.2) with `set -m` does not see a job stop; dash is `/bin/sh` on Ubuntu. If a run does not finish, the test kills the child's group, the job's group, and the shell (S4).

| Test                                                                    | Before the fix                                  | After the fix |
| ----------------------------------------------------------------------- | ----------------------------------------------- | ------------- |
| `an_interactive_child_owns_the_terminal_and_reads_it`                   | fails (child stopped, timeout)                  | passes        |
| `ctrl_c_reaches_an_interactive_child_once_from_the_terminal`            | fails (child not in the foreground)             | passes        |
| `ctrl_z_suspends_the_job_and_fg_resumes_the_child`                      | fails (child stopped, timeout)                  | passes        |
| `a_forwarded_sigterm_ends_a_stopped_child`                              | fails (claudectl hangs)                         | passes        |
| `claudectl_owns_the_terminal_again_after_an_interactive_child`          | passes (not counted as red, S4)                 | passes        |
| `a_forwarded_sigint_ends_a_stopped_child`                               | fails (claudectl hangs)                         | passes        |
| `a_child_that_exits_in_the_background_leaves_the_terminal_to_the_shell` | fails (background claudectl takes the terminal) | passes        |

CI runs these tests on Ubuntu and on macOS (`Build (macOS)`); the PR also records a manual macOS run. The live proof stays with HQ: a pinned Claude lane in a herdr pane shows the TUI, and Ctrl-C reaches Claude.
