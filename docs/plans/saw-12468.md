# SAW-12468: claudectl Feature Parity with codexctl

claudectl gets `label`, `status --json`, `statusline`, `rate` and a `claudectl claude` launcher that moves a session to another account when it hits a usage limit. `resets` is N/A for Claude. The work ships as six small PRs; the launcher needs a rule 57 challenge on one design choice: where a pinned Claude session keeps its state.

Sources: claudectl `origin/main` babe911 (v0.1.9) and codexctl `origin/main` 36b6711, read on 2026-10-06. Facts marked "verify" are not yet checked against Claude Code itself.

## PRs

1. **`exec` seeds onboarding state.** Every `exec` run gets a fresh `CLAUDE_CONFIG_DIR` (`src/exec.rs:1799`), so Claude shows its theme and login screens each time and never reaches the prompt (live proof on v0.1.9, 2026-10-06). Copy only the onboarding keys from `~/.claude.json` (`hasCompletedOnboarding`, `lastOnboardingVersion`; verified live on 2026-10-06: they skip the theme and login screens; `theme` is not a top-level key, so it is dropped) into the private dir, plus folder trust from the closest ancestor that recorded a decision (P1-1) and the current directory's external-import approvals. Never copy `oauthAccount`, tokens, or project history. Test: the private `.claude.json` holds exactly the allowed keys.
2. **`label`.** `label <alias> [text]`; blank text clears. Store `label` in `account.json` (`AccountMeta`, `serde(default)`) under the auth lock; a re-save keeps it. Show a Label column in `status` and `list` only when some account has one.
3. **`status --json`.** Shape `{version: 1, accounts: [...]}` with `alias`, `label`, `active`, the 5h and 7d `used_percent` and `resets_at`, `plan` (from `subscription_type`), `billing_class`, `usage_age_seconds`, `usage_stale`, `error`. `billing_class` is `usage_based` when `extra_usage.is_enabled` is true, `rate_limited` for a subscription plan with windows, else `unknown`. Recovery (PR 6) auto-selects only `rate_limited` accounts.
4. **`statusline`.** Reads a small cache that `status` writes for the active account (`~/.claudectl/statusline.json`, no credentials). Output as in codexctl: `{name} {weekly_remaining}% wk · {time_to_reset}`, plus 5h when present. Silent (exit 0) when the read exceeds 150 ms, the sample is older than 5 minutes (the usage cache lifetime; 120 s as in codexctl would leave the line empty almost always, because only `status`, `use` and `switch` write the sample), the sample's account UUID no longer matches the active profile, the active account changed, or data is missing. It can serve as Claude Code's `statusLine` command.
5. **`rate`.** codexctl counts responses in Codex's SQLite log; Claude Code has no such log. First step: check whether Claude Code transcripts (`projects/**/*.jsonl`) record API errors with status 429 (verify). If they do, count 2xx turns and 429s per account for the last N minutes; if not, record `rate` as N/A with that reason. This PR waits for PR 6, because transcripts only survive with a persistent state dir.
6. **`claudectl claude` launcher with recovery.** Design below; rule 57 challenge before code.

## Launcher Design (Rule 57 Challenge)

Keep the codexctl rules: keep the cwd; never auto-select `usage_based` or `unknown` accounts; a billing switch needs a y/N on a TTY or `--allow-billing`; no reset logic (N/A).

**Choice A: where session state lives.** `exec` removes the config dir at the end of each run (`src/exec.rs:790`), so `claude --resume` cannot find a session from an earlier run or another account.

- A1, recommended: a persistent per-lane state dir, `~/.claudectl/lanes/<lane>/` (0700), used as `CLAUDE_CONFIG_DIR` for every account the lane runs on. The token still arrives only through the inherited pipe, and the dir holds no credentials (checked before each launch). Sessions, onboarding, and settings survive a switch, so `claude --resume <id>` works on the next account.
- A2: keep a fresh dir per run and copy `projects/` in and out. More moving parts, and a crash loses the session.

**Choice B: limit detection.**

- B1, recommended: poll `/api/oauth/usage` for the lane's account through the existing usage cache. A window at 100 % is a limit. No terminal parsing, but the poll lags by up to the cache TTL.
- B2: parse Claude's limit message in the terminal output inside a pty, as codexctl does for Codex. Faster, but tied to Claude's UI text (verify the text).

Recommendation: A1 with B1, and B2 as a later option only if the lag proves to matter.

**Recovery flow (A1, B1).** On a limit: stop the Claude child (SIGINT, then teardown), pick the next `rate_limited` account with room (ranking as in `use` with no alias), relaunch on the same lane dir with `--resume <session id>` and the recovery prompt. Take the session id from the newest transcript under the lane dir for the cwd (verify the path layout). Cap recovery at 3 per hour, as in codexctl.

## HQ Changes (Rule 57 Challenge, 2026-10-06)

HQ approved this plan with changes; they replace the matching parts above.

- P1-1 (PR 1): folder trust from the closest ancestor that recorded `hasTrustDialogAccepted`, under its own key; no extra trust. Implemented as the closest `true`: Claude Code 2.1.292 ignores a nearer `false` (it writes `false` entries on its own), checked live.
- P1-2 (PR 6): choice A1, modified. Keep only `projects/` (transcripts) between runs. Rebuild `.claude.json` from the PR 1 allowlist at every launch and every account switch; never carry account state (`oauthAccount`, overage consent, model and grant caches) to another account.
- P1-3 (PR 6): choice B3. Detect a limit from transcript records (`"error":"rate_limit"` with `"isApiErrorMessage":true`) in the newest lane transcript, then confirm with one `/api/oauth/usage` read before a switch. No polling and no screen parsing.
- P2-4 (PRs 3, 6): a window at 100 % includes `seven_day_opus`, `seven_day_sonnet` and the Fable `limits[]` entry; `status --json` shows them.
- P2-5 (PR 6): an explicit launch on a `usage_based` account needs a y/N or `--allow-billing`; recovery never picks one; with no room, stop and report.
- P2-6 (PR 6): reclaim the terminal foreground before a relaunch; a per-lane lock on the lane dir; on macOS, assert that no Keychain entry exists for the lane dir's config path.
- P2-7 (PR 5, after PR 6): `rate` counts transcript `rate_limit` errors and assistant turns; the launcher logs account start and end so turns map to accounts.
- P3-8 (PR 1): retry once on a parse error, then warn on stderr.
