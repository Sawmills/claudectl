# SAW-12668: plain `claude` runs through `claudectl server run` (PATH shim)

Goal: typing `claude` (no alias) in a terminal, a script, or a herdr lane starts Claude through `claudectl server run <account>`.

## Facts from the code (main d436935)

- `claudectl server run <alias> [--claude <path>] -- <args>` already does all the safety: qualified build snapshot, env scrub, server token on a pipe, no billing fallback, revision follow (v0.1.17).
- `--claude` defaults to `claude`, and `program()` looks it up on PATH. With a shim first on PATH, that lookup finds the shim: recursion. So the shim always passes `--claude <real path>`.
- `RunSlot` is per process, so a nested `claude` call inside a shimmed session (a lane's Bash tool running `claude -p`) starts its own `server run`. That is the wanted behavior.
- `claudectl launcher` (local exec) pins a private claudectl copy. The shim does not: it must pick up claudectl upgrades, because revision-follow fixes ship in claudectl.

## Design

- `claudectl shim install --account <alias> [--claude <path>] [--dir <dir>]`
  - Dir default `~/.local/claudectl/bin`. Writes `<dir>/claude` (mode 0755), a POSIX sh script with the marker line `# claudectl-shim v1`.
  - Real Claude: `--claude`, or the first `claude` on PATH that is not a shim (marker check). It is recorded as given, not canonicalized, so the native installer's `~/.local/bin/claude` symlink keeps following updates. Install refuses when the real path resolves to the shim or to any file with the marker.
  - claudectl: the absolute path of the running claudectl (`current_exe`), recorded.
  - Account: `--account` is required; install checks it is a server account (`client.account(alias)`). No automatic account choice in v1. A capacity-based picker (SAW-12555) can replace the fixed alias later.
  - Never touches `~/.local/bin/claude`, Homebrew, or shell rc files. Prints one line, `export PATH="$HOME/.local/claudectl/bin:$PATH"`, and says whether the dir is already first on PATH.
  - Refuses to overwrite a non-shim file at `<dir>/claude`; replaces its own shim on re-install.
- The script:

  ```sh
  #!/bin/sh
  # claudectl-shim v1: generated by `claudectl shim install`; re-run it to change.
  real='<real>'
  if [ "${CLAUDECTL_SHIM:-}" = off ]; then exec "$real" "$@"; fi
  case "${1:-}" in -v|--version|-h|--help|update|doctor|install) exec "$real" "$@" ;; esac
  exec '<claudectl>' server run '<alias>' --claude "$real" -- "$@"
  ```

  Values are shell-quoted at render (`'` escaped). The file holds no credential.
- `claudectl shim status`: dir, script present, account, real Claude path and whether it resolves, claudectl path, and whether PATH order resolves `claude` to the shim. Exit 1 when broken.
- `claudectl shim uninstall`: removes `<dir>/claude` only when it carries the marker.
- `server run` guard: refuse a `--claude` program whose file starts with the shim marker (defense in depth when a user passes the shim by hand).

## Tests first (devbox, rule 67)

1. Install writes an executable script with the marker, the quoted alias, the real path, and the claudectl path; an alias or path with `'` stays quoted.
2. Install refuses: real path = shim, real path with the marker, a non-shim file at `<dir>/claude`, an unknown server account.
3. Script behavior (run the generated script with a fake claudectl and a fake claude that print argv): plain args give `server run <alias> --claude <real> -- args`; `CLAUDECTL_SHIM=off`, `--version` and `--help` run the real claude directly.
4. `server run --claude <shim>` refuses before any server call.
5. Uninstall removes only a marked file; status reports PATH order and a missing real binary.

## Phase 2 option (later, not in this PR)

Research `~/Code/.fleet/codexctl/research-claude-keychain-feed.md` (HQ, 2026-10-08): Claude 2.1.295 runs on an access-only `.credentials.json` (no `refreshToken` key) in a private `CLAUDE_CONFIG_DIR`. It reloads the file when its mtime changes, and it never writes the file back. So a feeder could write each new server access token into that file, and Claude would pick it up without a restart.

Trade-off: a private config dir lost the `~/.claude` sessions and skills before #40 (`server run` keeps the host Claude config since then). A phase 2 design must keep the host config, or copy what Claude needs, before it can replace the restart-based revision follow. Phase 1 stays "shim -> `server run`".
