# SAW-12585: claudectl server home page and dashboard

Goal: `/` on the claudectl server leads to Google sign-in and then a read-only dashboard, the same experience as the codexctl server (#153 look, approved by Amir).

## Design

- Port codexctl `src/central/dashboard/` into `src/server/dashboard/`: `style.css`, `page.html`, `landing.html`, `accounts.html`, `error.html`, and the render module (escape, bars, reset times, empty state). Drop Codex-only parts: credits, banked resets, loans, billing class, fonts route (system font stack, as in the enrollment pages). No JS in v1; a `<noscript>`-free `meta refresh` of 60 s keeps the numbers current.
- Routes: `GET /` (landing, or redirect to `/accounts` when signed in), `GET /accounts`, `GET /accounts/sign-in`, `POST /accounts/sign-out`.
- Sign-in reuses the existing OIDC client, PKCE, nonce, `hd` and `company_email` checks and the allow list in `enrollment.rs`. The SSO login row gets a destination: `Enrollment(device)` or `Accounts(login-cookie digest)`.
- Sessions live in the store as enrollment rows of kind `session` (sealed user ID, 1 h expiry), so both replicas see them. No schema change: `put_enrollment` gets a TTL parameter. Sign-out consumes the row.
- Cookies: `__Host-claudectl-session` and `__Host-claudectl-login`, `HttpOnly; Secure; SameSite=Lax; Path=/`. The login cookie binds the callback to the browser that started it.
- CSRF: the only POST is sign-out. It requires `Origin` equal to the public URL (codexctl pattern) and `SameSite=Lax`.
- Data (owner-scoped by the session user, as every store read already is):
  - Accounts: alias, available or unavailable, migration state (`not_migrated`, `pending`, `unrotated`, `rotated`), 5 h and 7 d bars with reset times from the cached usage (`engine.usage(cached = true)`; the page never calls Anthropic).
  - Machines: name and revoked state from `store.machines(user)`. No last-seen column exists, so the page omits it. Revoke API exists (`/v1/devices/revoke`), but it needs a machine bearer token; v1 stays read-only. A browser revoke is a follow-up.
  - Empty state: one line plus `claudectl server migrate --all --exclusive-owner`.
- Errors: `company_identity_required`, `user_not_allowed`, expired state reuse `error_page` with sign-in wording for the dashboard path.
- No token, refresh grant, or account UUID goes into a page or a log line. CSP with hashed inline style, `no-store`, `nosniff`, `frame-ancestors 'none'`.

## Tests first (focused, `tests/server_dashboard_test.rs` plus unit tests)

1. Unauthenticated `GET /` shows the sign-in page; `GET /accounts` redirects to `/accounts/sign-in`.
2. Sign-in with a personal Google account (no `hd`) returns 403 `company_identity_required` as an HTML page.
3. Two users with accounts: a signed-in user sees only own aliases and machines.
4. Sign-out without a same-origin `Origin` returns 403; with it, the session row is consumed.
5. Callback with a missing or mismatched login cookie returns 401.
6. Render: synthetic snapshot shows bars, reset times, empty state; no secret strings in HTML.

## HQ changes M1 to M5 (rule 57 answer, applied)

- M1: `SsoLogin.destination` is an untagged enum, `Accounts { browser }` or `Enrollment { device }`, with no default. A row written before this change (`device` only) parses as `Enrollment`; a row with neither field is refused. The Accounts branch never reads a device row or writes an approval; the Enrollment branch never sets a session. One test per direction.
- M2: every `/accounts` request rechecks `user.enabled` and the allow list, as `authorize` does for machine tokens. The dashboard callback calls `record_user`.
- M3: the page reads the stored usage observation (`Engine::cached_usage`), without the poll lock and without loading the grant. It shows "Updated N min ago", a stale state, or "No usage data yet". A failed read for one account shows as no data, counts in `usage_unavailable`, and never fails the page.
- M4: users enrolled by an operator on the server host (`register`, user ID `digest("admin\0" + email)`) are a different server user from the Google sign-in (`digest(issuer + "\0" + subject)`). Their accounts do not show on the dashboard; the empty state says so. The dashboard never matches users by email.
- M5: the callback creates a new random session secret and stores only its digest; it clears the login cookie. Sign-out (same `Origin` only; a missing `Origin` is 403) consumes the row and expires the cookie. A dead session cookie gets 401 and is expired.
- Growth note: expired session rows, like every enrollment row, are never deleted. One sign-in adds one small row; a cleanup job is a follow-up.
